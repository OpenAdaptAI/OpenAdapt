# PR 2297: keep postconditions on their producing steps

The compiler no longer moves a text postcondition onto a later click. A later
identity check, reversible risk label or matching demonstration frame does not
establish that an earlier action was read-only. Moving the check could also
carry it through an A-B-C chain. Every mined obligation now stays inline on its
original step; no replacement scheduling or timing-authority contract was added.

The existing moved-row proposal and bounded typed-echo rereads remain. The
reread loop lives in `runtime/typed_echo.py` to satisfy the existing replayer
size budget. It calls the same field verifier with the same baseline, scope,
mask policy, two-reread limit and one-second wait; it delivers no input. The
caller's unchanged-field retry and changed/unreadable refusal guards remain.

Accepted main `9e78e27da15e27a927033bf5c9392d01db7ad742` was merged normally,
without conflict. One compiler ownership model exercises read contracts,
selection, click writes, keyboard writes and two/three-step chains. Its genuine
pre-fix result was six failures and two read positives; the unsafe optimization's
two tests were replaced by this ownership model. Fixture-development failures
(path/module binding, optional notes and an unsupported typing/write section)
are separate from that baseline.
