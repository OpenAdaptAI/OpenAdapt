# Known-ID cross-check: dense record list, before and after

Generated by `python -m openadapt_flow.validation.known_ids_dense`. Synthetic data only.

## What was measured

- Surface: the dense record list of `benchmark/dense_surface` (40 rows, seeds 1, 2, 3, 4, 5), rendered in a browser and read by RapidOCR, with the replayer's band extraction and its 2x retry.
- Replay conditions: hi_res_arial, native_arial, small_dense, serif_drift. Click configs: click_name, click_action.
- Before: the shipped OCR verdict. After: the same two OCR reads passed through `runtime.known_ids.resolve_lookalike_abstain`, with every MRN in the seed's table as the complete known-ID list.
- Denominator for false stops: armed clicks on the correct row. Denominator for false accepts: armed clicks on the adjacent sibling row (same count).

## How to read this

In the `id_*` classes the sibling's MRN differs from the target's only by a look-alike glyph, and both are in the list. OCR cannot tell them apart, so the run still stops; that stop is correct, not a false stop in any useful sense. It is counted here so the denominator stays the full published one.

The remaining stops after the cross-check are band mismatches that have nothing to do with look-alike glyphs (dense-row OCR drops or garbles a name cell).

## Limits

- The lift is only as safe as the list is complete. A listed identifier set that misses a real look-alike record lets that record verify. The list must come from the system of record, not from the screen being checked, and the operator attests completeness.
- One fixture, one OCR engine (RapidOCR), synthetic rows. A different renderer, font or OCR engine moves these numbers.
- The two reads are the native frame and a 2x upscale of the same frame. They are independent OCR passes, not independent captures.
