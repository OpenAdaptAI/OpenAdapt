# Control overlay contract

OpenAdapt Desktop projects existing recording and execution events into a
compact always-on-top window. It is a view and control surface, not a second
runtime. Normal operation asks the OS to exclude the window from screen
capture; an operator can deliberately enable presentation mode in Settings.
The overlay remains hidden unless that native capture policy is acknowledged.

## Non-interference contract

During `observing`, `recording`, `executing`, `verifying`, `pausing`,
`resuming`, and `stopping`, the native window is non-focusable and ignores OS
cursor events. Before applying click-through, Desktop hides the window; it shows
the overlay again only after the OS acknowledges both pointer and focus policy.
Those phases render no overlay controls. The recording Stop action remains in
the main Desktop window, outside the target surface.

The overlay becomes interactive only while paused or after a terminal outcome,
when no observation or actuation is in flight. Presentation mode changes only
capture inclusion; it never changes pointer or focus behavior. The overlay does
not expose an emergency process kill: execution interruption is not currently
a runtime capability, and killing a possibly delivered consequential action
would require an explicit uncertain-outcome contract before it could be offered
safely.

The reusable presentation interface is the Tauri event
`overlay://frame`. Its payload is
`openadapt.control-overlay-frame/v1`, defined in
`src/overlay/contract.ts`:

```json
{
  "schema_version": "openadapt.control-overlay-frame/v1",
  "state_id": "visible:executing:governed:regulated:2:5:no-pause:no-resume:no-stop",
  "event_sequence": 4,
  "observed_at_unix_ms": 1785000000123,
  "observed_at_monotonic_ms": 1234.5,
  "visible": true,
  "phase": "executing",
  "workflow_label": "Governed workflow",
  "mode": "governed",
  "profile": "regulated",
  "step": { "current": 2, "total": 5 },
  "controls": { "pause": false, "resume": false, "stop": false },
  "status": "Executing with verification gates",
  "presentation": true
}
```

`state_id` identifies the semantic state, `event_sequence` orders repeat visits,
and the wall plus monotonic timestamps align it to full-window or Playwright
video without depending on the system clock staying unchanged.

Visible lifecycle states use the same vocabulary as execution reporting:
`observing`, `recording`, `executing`, `pausing`, `paused`, `resuming`,
`stopping`, and `verifying` are transient; `verified`,
`completed_unverified`, `halted`, `failed`, and `rolled_back` are terminal.
`idle` is emitted only for the hidden initial state. A legacy `done` event never
becomes `verified` unless it also carries the precise `VERIFIED` runtime outcome.
Frame `controls` describe actions available on the overlay itself, so they are
all false throughout non-interactive observation and actuation phases even when
the main Desktop window offers a safe recording Stop action.

The broadcast frame is always the presentation-safe projection. It contains no
workflow ID, local workflow name, screenshot, target, action text, typed value,
identity evidence, URL, application timestamp, log line, exception, or report
body. The two contract timestamps are generated by the local overlay receiver
only for deterministic media alignment.

A deterministic demo compositor should subscribe to `overlay://frame`, persist
the frames beside (not inside) the raw evidence, align them by monotonic time,
and render the same semantic fields over a presentation derivative. Page-only
Playwright video cannot contain a native window, so it must use this composition
path (or switch to full-window capture) rather than claiming the native overlay
was recorded directly. Injecting controls into the target application's DOM is
not the normal path; a clearly labeled demo-only injection may be used only as a
fallback when post-composition is unavailable.

## Demonstration coach

The overlay can also coach a first demonstration: the person clicks on the live
system, and a local agent suggests the next move. That design, the
`overlay://coach` payload, the auth-pause copy, and the loopback IPC recipe
live in [`COACH_HUD.md`](COACH_HUD.md).

`overlay://coach` is local-only. Do not write it into evidence, `report.json`, a
Seal, Cloud ingest, PostHog, or this `overlay://frame` contract. Hint text is
not a Types field. A compositor that consumes `overlay://frame` already has
the closed vocabulary it needs.
