| Verify a write to an API or SaaS system with no database to diff: `openadapt proxy --api systems.tx.yaml` serves `api_read` and `api_write` beside the SQL tools on the same MCP endpoint and keeps the API credentials out of the agent's environment. Each write is sent once under a key derived from the task and the record, never the payload. A retry returns the first result, a regenerated payload is refused, and a crash between the send and the ledger is recovered by finding the write. The key goes out as `Idempotency-Key` where the API honors one, or as a FHIR conditional create. The record is then read back and judged with the tx codecs, including `null_empty`. The system's own event or audit log is read from an id-placed cursor, and the write's own event must appear with no other resource changed by the same credentials. A FHIR `AuditEvent` search, an event stream and a REST activity feed are all declared as data in the tx file. Every outcome gets a `record/run/v1` receipt. Scope is the resource and the actor: changes by other callers, and changes the log doesn't record, aren't checked. A whole-record (`replace`) update or a delete over another caller's edit is refused by the server when the route declares a `precondition` (`If-Match` from the read's `ETag` or a version field) with enforcement evidence: a probe recorded in the pack, or one the adapter runs once per route. Without a precondition it is never `VERIFIED`, only `COMPLETED_UNVERIFIED` (`unconditional_write`; `precondition_unproven` without evidence), and `api_write` reports it as an error.
